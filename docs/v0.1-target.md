# HarnessVLN v0.1 可验收目标

状态：范围已确定，以下项目全部通过后才称为 v0.1 兼容。

## 1. “兼容”的定义

兼容模拟器必须有真实 Environment adapter、官方 Bench loader、私有评分器和完整 split
运行入口；兼容模型必须能加载官方 checkpoint，通过同一个 `VLNNavigator` 接口主动观察和
移动，并与官方 evaluator 做固定 episode 对照。只有 schema、mock 或 import 成功不算兼容。

目标不是模拟器与模型的 3x3 笛卡尔积，而是下面列出的已验证组合。

## 2. 模拟器与 Bench

| Environment | 首发 Bench | v0.1 固定范围 | 评分 |
|---|---|---|---|
| Habitat-Lab/Sim 0.2.4 | R2R-CE | `R2R_VLNCE_v1-3/val_unseen`，MP3D | SR、SPL、NE、OS |
| Habitat-Lab/Sim 0.2.3 | GOAT-Bench v1 | HM3D-Semantics `val_unseen`；360 个复合 episode、2669 个 goal | Success、SPL（整体及按 goal modality） |
| AI2-THOR 2.7.2 / RoboTHOR | RoboTHOR ObjectNav 2021 | 官方 validation episodes；目标类别转成 `Find the <object>.` | SR、SPL |
| Isaac Sim，经 InternNav 的 `internutopia` 入口 | VLN-PE R2R | H1、MP3D-PE、`val_unseen`，v0.1 单 lane | SR、SPL、NE、OS |
| Isaac Sim 4.5.0，经 VLNVerse 的 `vln_multi` 入口 | VLNVerse | H1、Kujiale、`coarse/val_unseen`，v0.1 单 lane | SR、SPL、NE、OSR、nDTW、TL |

依据：[VLN-CE](https://github.com/jacobkrantz/VLN-CE)、
[GOAT-Bench](https://github.com/Ram81/goat-bench)、
[RoboTHOR Challenge](https://github.com/allenai/robothor-challenge)、
[InternNav VLN-PE 配置](https://github.com/InternRobotics/InternNav/blob/main/scripts/eval/configs/h1_internvla_n1_async_cfg.py)、
[VLNVerse 官方评测](https://github.com/sihaoevery/vlnverse_emr/tree/vlnverse)。

每个 Bench 负责 episode reset 数据和私有目标；Agent 只收到 `NavTask`。THOR 的
`lastActionSuccess=false` 只是动作失败，不是任务结束。Isaac 的物理、控制、相机频率留在
adapter 内，Runner 不接管 step loop。VLN-PE 和 VLNVerse 各自保留原生启动链，由各自
Bench 选择不同 Environment factory，不抽成一个包含大量分支的通用 Isaac 入口。
VLNVerse 运行环境固定为官方的 Isaac Sim 4.5.0/PyTorch 2.5.1；数据与 checkpoint 约
500 GB，不随 Harness 分发。完整 split 按官方 chunked 方式运行，在完整 episode 边界
回收并重启 native worker，避免长进程中的碰撞体/内存累积，Runner 仍不参与逐步控制。

`NavTask` 是 Goal 流而非固定单指令。R2R-CE 等任务只有一个 `NavGoal`；GOAT 的一个
episode 有 5–10 个 object category、language description 或 image goal，未来 goal 不
提前暴露。Harness 对整个 episode 只打开一次 Environment、Agent、VLN session 和
Memory。Agent 调用 `nav.goal.finish` 后，GOAT adapter 映射为原生 `subtask_stop` 并返回
下一个 Goal，不 reset 位姿或任何上述组件；最后才调用 `nav.stop`。每 Goal 500 个动作的
上限由 TaskSession/adapter 执行并发布 `goal_changed`，Runner 不代替 Agent 注入 STOP。
官方 GOAT 观测含 360x640 RGB、Depth、GPS+Compass 相对位姿和当前 Goal；动作为前进
0.25 m、左右转/抬头/低头 30°，成功阈值为 1 m。

## 3. 三个 VLN 模型

| `VLNNavigator` | 首发验证组合 | 观测/运动要求 | 插件内部状态 |
|---|---|---|---|
| `StreamVLNNavigator` | Habitat + R2R-CE | RGB、Depth、pose、内参；0.25m/15° 离散动作 | SlowFast 历史、KV cache、动作队列 |
| `JanusVLNNavigator` | Habitat + R2R-CE | RGB；0.25m/15° 离散动作 | 语义/空间隐状态、VGGT 状态、图像历史 |
| `DualVLNNavigator` | Habitat + R2R-CE；Isaac + VLN-PE/VLNVerse | RGB-D；离散/trajectory，含相机俯仰 | 完整 System 1/System 2、异步线程、pixel/latent/trajectory 状态 |

三者都暴露 `vln.navigate.start/status/cancel`。Job 内部执行
`nav.observe -> infer -> nav.move.*`；模型输出的 `STOP` 结束当前 VLN Job，只有 Agent
能调用 `nav.stop` 结束完整任务。DualVLN 的大小脑不拆成 Harness 模块。

每个 adapter 用普通 `requirements` 数据声明 channel、action set、步长、转角、frame 和
单位；Harness 启动时与 Environment 提供的数据比较。它不是新插件接口或协商系统，
只用于阻止“工具同名但动作语义不同”的错误组合。

```yaml
requirements:
  observation_channels: [rgb, depth, pose, camera_intrinsics]
  motion:
    tool: nav.move.discrete
    actions: [forward, turn_left, turn_right]
    forward_m: 0.25
    turn_deg: 15
```

模型依据：[StreamVLN](https://github.com/InternRobotics/StreamVLN)、
[JanusVLN](https://github.com/MIV-XJTU/JanusVLN)、
[DualVLN 的 InternNav 实现](https://github.com/InternRobotics/InternNav/blob/main/internnav/agent/internvla_n1_agent.py)。

RoboTHOR ObjectNav 只验收 THOR Environment 与 Bench，不宣称三个 R2R checkpoint 能
零训练迁移过去。模型进程可使用各自 conda/container；Harness 中的插件只是本地/RPC
adapter，避免 CUDA、Transformers 和模拟器版本互相污染。

GOAT 的三种 goal modality、30°/look 动作和长期状态也不满足三个 R2R checkpoint 的
既定 contract；加入 GOAT Bench 不等于 StreamVLN、JanusVLN 或 DualVLN 可直接运行
GOAT。v0.1 用满足三模态 contract 的真实 Agent 插件跑完整 split，验收 Environment、Goal 流和
官方 scorer；后续 GOAT policy 仍以普通 Agent/VLN 插件接入，不修改 Harness。

## 4. 两种 Agent Core

### `PassthroughVLNAgent`

把当前 `NavGoal` 原样传给一次 `vln.navigate.start` 并轮询 Job。单 Goal 任务成功后直接
`nav.stop`；复合 Task 则调用 `nav.goal.finish` 取得下一 Goal 后重复，期间不重建 Agent、
VLN session 或 Memory。它不读取观测、不改写 prompt、不直接移动。

### `SubtaskNavigationAgent`

对每个 Bench Goal 执行 `decompose(goal) -> list[PlanStep]`，按顺序为每个 PlanStep 启动
VLN Job；每轮可先 `spatial.search`，Job 成功后可 `spatial.remember`。当前 Goal 完成后，
若 Task 还有下一 Goal，则先 `nav.goal.finish` 再继续，避免把 Agent 内部 PlanStep 与 GOAT
Goal 混为一层；最后才 `nav.stop`。v0.1 只做有界顺序循环、失败即终止，不做动态 DAG、
多 Agent、在线学习或复杂重规划。测试使用确定性 decomposer，真实配置可注入一个 LLM
decomposer，但 Agent 生命周期不变。

## 5. Dummy 空间记忆

首发只实现 `DummyLandmarkMemory`，用于验证插件、工具和跨任务持久化：

```text
landmarks.json
  id, source_task_id, frame, pose?[x,y,yaw], text

spatial.remember(frame, pose?, text) -> id
spatial.search(query?, frame?, near_pose?, top_k) -> landmarks
```

查询采用确定性的文本包含匹配；提供 `near_pose` 时，同 frame 内按二维欧氏距离排序，
再以 id 打破平局。任务关闭时原子写回 JSON；GOAT 的多个 Goal 共用同一实例，两个 Task
复用同一目录即可验证跨 Task 记忆。
它没有 embedding、拓扑边、route、后台建图或模型隐状态，也拿不到运动工具。

## 6. Release Gate

1. 五条 Environment/Bench 组合各完成一次官方 validation split 的加载、运行、评分并保存 manifest；
   scorer 在人工 golden trajectory 上与官方定义一致。
2. 三个模型各在固定的 3 个 R2R-CE episode 上，与其官方 evaluator 对照 action trace、
   terminal 和最终 pose；DualVLN 另各跑至少 3 个 VLN-PE、VLNVerse episode。
3. 两种 Agent 分别与三个 VLN adapter 完成真实 episode；替换 Agent 时 Runner、Env、
   VLN 和 Bench 源码不变。
4. GOAT `val_unseen` 必须加载 360 个复合 episode/2669 个 Goal；每个 episode 的
   `Agent.run`、Environment reset 均恰好一次，Goal 切换不改变 session/pose/memory id；
   验证 500-action 自动推进、1 m success 和三种 modality 的官方评分。
5. Dummy Memory 通过 `Task A remember -> 关闭 -> Task B 新实例 search`，并验证
   `writeback=false` 不修改文件。
6. 验证 VLN Job 多频运行、cancel、timeout、stop fencing；Habitat/THOR 整任务并行度
   至少为 2；两个 Isaac 入口的 v0.1 并行度均明确为 1；VLNVerse 验证 chunk 边界续跑
   不漏 episode、不重复评分。
7. 每次结果记录 simulator、dataset、checkpoint、upstream commit、seed 和配置摘要；
   缺少真实运行 artifact 的组合保持“未验证”，不进入兼容列表。
