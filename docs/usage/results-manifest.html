结果与 Manifest ​

run 模式每次执行写出一个 manifest.json。它同时记录 Runner 套件、Agent 组合、各 Bench 结果 和复现来源；env 交互模式当前只显示单 Task 结果，不写批量 Manifest。

顶层 aggregate_metrics 汇总整个 Runner 套件，Bench 内的同名字段只汇总该 Bench。当前都只对 评分成功 record 中存在的有限数值做算术平均；正式发布仍应由 Bench 验证是否符合官方 evaluator 聚合语义。

每个 Bench 的 error 保存构造、case 流或调度前验证错误；cleanup_errors 保存 Bench 级共享 资源回收失败。失败 Bench 可以没有 records，但不会阻止兄弟 Bench 写入同一 Manifest。

每个 record ​

字段含义
index / case_idBench 输入顺序和稳定 case 身份
errorcase-level 异常文本；无异常时为 null
error_stagestack、execution、score；与 error 同时出现
metrics通过契约校验并归一化为有限 float 的逐 case 指标；评分失败时为空
execution_idHarness 执行身份；未进入 Harness 时为 null
terminalTask 的 status、reason、actor
environmenttrajectory、动作、native metrics 等适配器结果
cleanup_errors主流程结束后的清理失败，不覆盖 terminal
audit全部 ToolEvent

四类失败必须分开看 ​

bash
jq '{
  task_failed: [.benchmarks[].records[] |
    select(.terminal != null and .terminal.status == "failed")] | length,
  bench_error: [.benchmarks[] | select(.error != null)] | length,
  case_error: [.benchmarks[].records[] | select(.error != null)] | length,
  cleanup_error: ([.benchmarks[].cleanup_errors[]] +
    [.benchmarks[].records[].cleanup_errors[]]) | length
}' runs/EXPERIMENT/manifest.json

  • task failure：任务进入 Harness 后由 Agent、Environment 或 timeout 得到失败 terminal；
  • Bench error：整个 Bench 未形成正常 records，例如构造或 case stream 抛异常；
  • case error：单个 case 的 stack、执行或评分阶段抛异常；
  • cleanup error：停止共享 VLN、单 Task Environment 或 Memory 时失败。

CLI 将这些失败都计入非零退出码，避免正常指标掩盖资源清理问题。

error_stage 明确证据完整度：

stage已完成到哪里result
stackAgent/Env/VLN/Memory stack 尚未构造完成null
executionstack 已构造，但 NavigationHarness.run_task 抛异常null
scoreTask 已完成，只有 Benchmark.score 失败保留 terminal、environment、cleanup 与 audit

因此 score 错误不会伪装成“任务没有运行”；该 record 的 metrics 为空，但导航执行证据仍可诊断和复核。 评分器返回空映射、非法名称、布尔值、非数值或 NaN/Infinity 也按此规则隔离，非法值不会进入指标 聚合或 Manifest 的 metric 字段。

查看控制权与动作来源 ​

bash
jq '.benchmarks[0].records[0].audit | sort_by(.sequence)[] |
  {sequence, actor, name, arguments, outcome, error}' \
  runs/EXPERIMENT/manifest.json

核对配置身份 ​

bash
jq '{config_sources, config_digest, provenance,
  benches: [.benchmarks[] | {name, split, validation_status}]}' \
  runs/EXPERIMENT/manifest.json
1
2
3

config.runner 是 Runner 及其引用的 Bench/Env 解析图，config.agent 是 Agent 及其 VLN/Memory 解析图。digest 来自解析后的 canonical JSON；源文件绝对路径另行保存，便于追踪引用与 extends。

写入保证 ​

writer 在输出目录创建临时文件，写入、flush、fsync 后用 os.replace 原子替换 manifest.json。同一 output root 的后一次执行会覆盖主 Manifest，需要保留历史时应使用唯一目录 或由外层实验系统归档。

schema_version 当前为 2。error_stage 是 v2 record 的兼容新增字段。消费者应先检查版本并容忍 record 新增字段；改变现有字段语义或层级时 必须提升版本，不应依赖 JSON key 顺序。
