配置叠加 ​

CLI 按组件接收具名 YAML 参数，再以确定顺序深度叠加：

text
Bench -> Agent -> Environment -> model-specific Env overlay -> VLN -> Run override
1

每个文件只描述一个关注点，因此换 Agent 不必复制环境参数，做单例 smoke 也不必修改正式 run。

--benchmark 选择 case loader 与评分器，--environment 选择 Habitat、AI2-THOR、Isaac 或真机 执行后端。二者不共享职责：Bench 持有私有真值，Environment 持有原生 session。

一个完整组合 ​

bash
PYTHONPATH=src python -m harness.cli \
  --benchmark config/benches/r2r_ce.yaml \
  --agent config/agents/passthrough.yaml \
  --environment config/envs/habitat_r2r.yaml \
  --vln config/vln/streamvln.yaml \
  --run config/runs/r2r_streamvln.yaml \
  --overlay config/runs/smoke_one.yaml

使用标准模型 AgentLoop 时把 --agent 换成 config/agents/normal_agent.yaml。该配置声明了 VLN 和 Memory 工具，所以组合中也必须提供对应 --vln 与 --memory；纯直接导航配置应覆盖 stack.agent.params.tools，只保留所需的 nav.*。OpenAI key 由 SDK 从进程环境读取，不进入 YAML。 Dummy 完整组合使用 config/runs/dummy_normal_agent.yaml，不要叠加带有 poll_period_s 的 dummy_passthrough.yaml。

CLI 参数 ​

参数作用是否可重复
--benchmarkCase 加载、私有真值与评分否，必填
--agentAgent Core否，必填
--environment模拟器或真机中间件是，至少一个
--vln完整 VLN navigator否，可选
--memory空间记忆否，可选
--runRunner、输出与 provenance否，必填
--overlay最终局部覆盖，例如单例 smoke是，可选

重复 --environment 专门用于模型传感器 profile 等环境层叠加；重复项保持出现顺序。所有 --overlay 始终最后应用。

ComponentSpec ​

每个组件支持：

字段含义默认值
factorymodule:object 可调用对象必填
params构造函数关键字参数{}
scopetask 或 VLN 可用的 runtask
serial声明进程级/共享资源要求串行false

Environment factory 额外收到 case=BenchmarkCase。其他 params 原样传给 factory，不需要在核心 代码增加插件专用字段。

scope 与 parallelism ​

配置加载会拒绝 run-scoped Agent、Environment、Memory。VLN 可使用 scope: run，但当前 StackFactory 将其视为 requires-serial。任一组件 serial: true 或 Memory writeback 启用时， runner.parallelism 必须为 1。

seed 的当前边界 ​

runner.seed 当前会进入解析配置、digest 和 Manifest，但 runtime 尚未统一注入 Python、NumPy、 Torch、Environment 与 worker。因此它是实验意图记录，不是全栈确定性保证。需要复现实验时，还应 在具体插件/模拟器配置中固定 seed，并记录上游版本。后续若实现统一 seed service，必须保留插件 显式覆盖能力。

provenance 应记录什么 ​

建议记录 model/checkpoint/upstream commit、dataset revision/hash、simulator build、adapter version、 组合名与验证范围。provenance 不参与运行逻辑，但进入 Manifest，不能用它替代真实配置字段。
